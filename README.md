# RPG Core + HUD

Клиентское расширение SillyTavern: отдельное состояние каждого чата, HUD на русском, ручные игровые часы и контекст ИИ. Первый этап **0.1.0**: сложные игровые механики ещё не реализованы. NPC Router не требуется.

## Установка

Целевая версия SillyTavern: **1.19.0**, проверенный upstream commit `06bde939fb1e9c4c8d8641d810f0a916b5bce127`. На более старых версиях manifest блокирует загрузку. Совместимость с более новыми версиями не гарантируется одним сравнением версии.

1. В SillyTavern откройте **Extensions → Install Extension**.
2. Вставьте `https://github.com/stvibe/st-rpg-core`. Для проверки PR до слияния выберите ветку `feat/rpg-core-hud-foundation` в поле branch установщика.
3. Перезагрузите страницу, откройте сохранённый одиночный или групповой чат. Справа внизу появится свёрнутый **RPG Core** над строкой ввода. Кнопка заголовка открывает и сворачивает HUD.
4. В «Статусе» сохраните имя, локацию и известные игроку сведения. В «Календаре» задайте игровую дату и время, затем положительное целое количество минут для таймскипа.
5. После важных изменений перезагрузите чат и проверьте состояние. В «Настройках» доступны повтор сохранения, восстановление предыдущей версии, импорт и экспорт.

Нужны разрешённые хостом UI extensions и Git на сервере SillyTavern. Пользователю не нужны server shell, серверный плагин, Extras, npm install или сборка. До публикации ветки установка из неё недоступна.

## Что работает на первом этапе

- Версионированное состояние в `chatMetadata.rpgCore`; резервная предыдущая версия в `chatMetadata.rpgCoreBackup`. Одиночные и групповые чаты обслуживаются одним адаптером.
- Дата не берётся с компьютера. Установка даты — явная коррекция, таймскип прибавляет игровые минуты. Отображение без конвертации в локальный часовой пояс. В JSON используется UTC-подобная запись с `Z` как стабильное представление **игровых**, а не реальных часов.
- Сообщения, генерация, retry, regenerate, swipe, stop и browser timers не продвигают время и не применяют события. Таймскип пока не расходует батареи, не исполняет расписания и не перемещает персонажей.
- Вкладки: Статус, Слух, Физиология, Устройства, Инвентарь, Навыки, Локации, Здоровье, Отношения, Календарь, Сюжеты, Журнал, Настройки. Tab/Shift+Tab перемещают фокус; стрелки/Home/End переключают вкладки.
- Сложные модули представлены обзором записей и раскрывающимся JSON-редактором с проверкой формы. Формулы/вероятности/thresholds — `rules: null` (TODO). Медицинские, финансовые и географические интеграции не выполняются.
- В контекст передаётся только известное игроку состояние. Скрытые `private.worldFacts` и `private.npcKnowledge` не выводятся в HUD и не включаются в injection. Неизвестные данные — `null`, не доказательство присутствия или нормального слуха.

## Структуры и ручной ввод

См. [схему состояния](docs/state.md). В редакторах модулей находятся **только сведения игрока**. Каждая запись массива обязана иметь уникальный `id` и явное `knownToPlayer: true`. Пример для вкладки «Инвентарь»:

```json
{"items":[{"id":"keys","knownToPlayer":true,"label":"Ключи","quantity":1,"owner":"player","container":null,"location":"Кухня","carried":false}]}
```

Это ручная запись, а не работающая механика переноса/расхода предметов. Скрытые NPC-факты храните исключительно в `private` полной копии. Редактор отклоняет неизвестные поля верхнего уровня модуля, некорректные параметры слуха, ID-дубли и неотмеченные как известные записи.

## Резервные копии и восстановление

**Полная резервная копия JSON** содержит всё, включая секреты; перед скачиванием требуется явное подтверждение. Храните её соответствующим образом. Полная копия импортируется в выбранный чат с резервированием предыдущего состояния. Экспорт сведений игрока — безопасная проекция для просмотра, **не импортируемый backup**.

«Восстановить предыдущую версию» меняет состояние на предыдущую сохранённую версию; операция сама создаёт новую ревизию и резервирует заменённую. Журнал хранит последние 200 типов действий без скрытых значений. ID применённых событий не удаляются при восстановлении, чтобы не применять их повторно. Лимиты v1: 1 МБ UTF-8 на состояние, 5000 ID/записей в массиве, глубина 15; архивирование долгих кампаний будет отдельным этапом.

Неизвестная версия или повреждённая metadata открывается без редактирования и не перезаписывается. Экспортируйте сам чат штатными средствами ST перед восстановлением через совместимую версию. Миграций из других схем пока нет: v1 — первая схема.

## Сохранение и ограничения

`saveMetadata()` SillyTavern может завершиться без исключения даже при серверной ошибке. HUD сообщает «передано на сохранение ST», а не гарантированный durable commit. Явное отклонение Promise показывает ошибку; данные остаются в памяти для экспорта/повтора. Проверка после reload и независимые полные копии важны.

Редактирование одной кампании из нескольких вкладок/устройств **пока не поддерживается**. Metadata не шифруются. Полная копия, исходники чата и другие расширения могут читать world truth. Prompt injection не очищает историю, World Info или карточки и не гарантирует соблюдение правил моделью. До отдельного этапа нет проверки/карантина AI-ответов и извлечения предлагаемых событий. Никогда не вводите секреты в публичные модули: `knownToPlayer: true` — ваше явное разрешение показать запись.

## Разработка и проверка

```sh
npm ci --cache /tmp/rpg-npm-cache
npm test
npm run check
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

Браузерные тесты используют системный Chromium и `playwright-core`; бинарник браузера npm не скачивает. Укажите путь к установленному Chromium. Runtime расширения не зависит от npm-пакетов. Браузерный contract harness проверяет настоящий entry/UI с подменённым ST контекстом; это не доказательство hosted/model E2E. Фактические результаты и оставшиеся проверки: [validation](docs/validation.md). Проверенные сигнатуры: [API](docs/api.md); исследование и ограничения: [feasibility](docs/feasibility.md).

## Необязательная интеграция

Entry module экспортирует `API_VERSION = 1` и `getPlayerSnapshot()`: глубокая копия только игроковой проекции, либо `null` при недоступном чате/отключённом расширении. Это API самого RPG Core, не SillyTavern. Пример для другого UI extension:

```js
const core = await import('/scripts/extensions/third-party/st-rpg-core/index.js');
if (core.API_VERSION === 1) {
    const snapshot = core.getPlayerSnapshot();
    // null означает недоступность; не выводить из неё присутствие NPC.
}
```

Путь зависит от имени папки установленного расширения; проверяйте его, обрабатывайте ошибку импорта. Обнаружение расширений и полный actor-scoped Router API из feasibility остаются будущим этапом. st-npc-router в этой реализации не меняется.
